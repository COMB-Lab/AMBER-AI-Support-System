>
>Meanwhile, is there a way to profile pmemd.MPI to see where it actually may
>be stalled?

There are detailed parallel timings at the bottom of the mdout file, and in
a log file (default name is "logfile", but you can change that with the "-l"
command-line flag.)

I'm not sure if these will provide much insight or not. Probably, you would
need to compare the timings on a machine where the problem shows up and one
where it doesn't.
