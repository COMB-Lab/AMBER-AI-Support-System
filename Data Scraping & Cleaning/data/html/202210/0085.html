Regarding the eigenvector comparison issue, you're exactly right that
the eigenvector sign has just been flipped - in my experience this
happening is dependent on the underlying BLAS/LAPACK implementation
and is not a cause for concern (since it doesn't matter what
"direction" the eigenvector points). I've actually addressed this in
the GitHub version of cpptraj by using RMSIP to do eigenvector
comparisons - but you can safely ignore this particular error.
