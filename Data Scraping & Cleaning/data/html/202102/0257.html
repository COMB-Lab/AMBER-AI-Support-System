Dear AMBER Users and Developers,

I performed TI simulations on AMBER20 with GPU in order to calculate
pKa of aspartate residues. The problem I encountered is that the
protein undergoes denaturation immediately when I carry out gpu
implemented TI, which was seen in different initial structures and
protonation states as well. However, on both AMBER16 and AMBER20 cpu,
there was no such a problem when I gave the same initial structure and
parameters. I have followed the online tutorial(and the reference
paper) and performed several successful TI on cpu thus far. After
minimization, I equilibrated each system for 5ns with clambda=0. Then,
the same equilibrated structure was given to production runs with
lambda values 0.1127, 0.5, and 0.88729. I use Langevin thermostat to
control temperature at 300 K and I don't use softcore potential.
During denaturation, there was no temperature increase due to
instability. As given in the AMBER20 manual, there are some gti
specific parameters but I took the default values. I also tried
gti_add_sc=0 ,but the sample problem was still observed. Moreover, I
ran trial simulations for 4-5 steps by turning off the Langevin by
setting ntt=1 and write energy values for each step to see how
energies fluctuate comparing AMBER20 cpu with AMBER20 gpu TI in the
absence of random number from Langevin dynamics. According to the
results, there was no significant difference between gpu and cpu. By
the way, standard md simulations run without any problem on the same
gpus. Am I missing something for the gpu case? What am I supposed to
add or change for the gpu implented TI? Any help/suggestion will be
greatly appreciated!
The input file for clambda=0.88729 alongside the output files for the
first 4 steps of amber20 gpu and cpu without Langevin are as follows:
