# Amber RAG — Archive + PDF, Ollama vs ChatGPT

A retrieval-augmented generation (RAG) system for questions about the AMBER molecular dynamics suite. A single query hits **two** vector stores in parallel — a persistent Chroma archive of AMBER mailing-list discussions and a FAISS index built from the AMBER25 PDF manual — merges hits by similarity score, and feeds the top results to an LLM.

This folder contains three notebooks designed to be run and compared:

| Notebook | LLM | Retrieval |
|---|---|---|
| `Sauce_Amber_RAG_Combined.ipynb` | Ollama (`llama3.1:8b`) | Yes — Chroma + FAISS |
| `Sauce_Amber_RAG_Combined_ChatGPT.ipynb` | OpenAI (`gpt-4o-mini`) | Yes — Chroma + FAISS |
| `Sauce_Amber_RAG_Combined_NoRAG.ipynb` | Both, side-by-side | No — bare LLMs |

Running all three gives you a four-way comparison per question: Ollama+RAG, ChatGPT+RAG, Ollama alone, ChatGPT alone.

## Prerequisites

You need all of the following in place before the notebooks will run end-to-end.

**Python 3.10 or newer.** The notebooks were developed against 3.10. A virtual environment is strongly recommended:

```bash
python3 -m venv .venv
source .venv/bin/activate    # macOS / Linux
# or:  .venv\Scripts\activate   # Windows
```

**Python packages.** Install in one shot:

```bash
pip install -U \
    chromadb \
    faiss-cpu \
    pypdf \
    sentence-transformers \
    langchain \
    langchain-core \
    langchain-community \
    langchain-text-splitters \
    langchain-huggingface \
    langchain-ollama \
    langchain-openai \
    jupyter
```

If you have an NVIDIA GPU and want faster embeddings, swap `faiss-cpu` for `faiss-gpu` and install a CUDA-enabled `torch` build first.

**Ollama running locally with the llama3.1:8b model.** Install Ollama from <https://ollama.com>, then in a separate terminal:

```bash
ollama serve              # leave this running
ollama pull llama3.1:8b   # one-time, ~4.7 GB
```

Confirm it's reachable: `curl http://localhost:11434/api/tags` should list `llama3.1:8b`.

**OpenAI API key.** Get one at <https://platform.openai.com/api-keys>. Export it in the shell you launch Jupyter from (so `os.environ` sees it):

```bash
export OPENAI_API_KEY="sk-proj-..."
```

On Windows PowerShell: `$env:OPENAI_API_KEY = "sk-proj-..."`. Cost note: running the full 8-question eval against `gpt-4o-mini` costs well under $0.05 at current pricing.

**The AMBER25 PDF manual.** The FAISS index is built from `Amber25.pdf`, which must sit in the same folder as the notebooks. Download it from <https://ambermd.org/Manuals.php> (file name and version may differ — rename to `Amber25.pdf` or change `PDF_PATH` in the Configuration cell of the notebook).

**The Chroma archive of AMBER mailing-list discussions.** The notebooks expect a persistent Chroma database at:

```
/opt/chromadb/data/prompt_db
```

with a collection named `amber_messages` containing ~43k vectors embedded with `sentence-transformers/all-MiniLM-L6-v2`. This database is **not** generated by these notebooks; it was built ahead of time from a scraped mailing-list archive. If you're reproducing on a fresh machine, you need either:

- A copy of the existing `/opt/chromadb/data/prompt_db` directory, or
- The ingestion script that built it (not in this folder)

If you only have one of those, change `ARCHIVE_DB_PATH` in the Configuration cell to point at your copy. If the path requires sudo (it's under `/opt/`), either run Jupyter with elevated permissions or `chown` the directory to your user.

## Run order

Launch Jupyter from this folder:

```bash
jupyter notebook
```

Run the notebooks in this order. Each one is independent — they don't share variables across kernels — but running them in order builds intuition.

### 1. `Sauce_Amber_RAG_Combined.ipynb` — Ollama + RAG (primary)

This is the main notebook and the one to treat as canonical.

Execute every cell top to bottom. The flow is:

1. **§1 Setup** — imports.
2. **§2 Configuration** — all knobs. Change paths or `K_TOTAL` / `MIN_PDF` here if you need to.
3. **§3 Embeddings** — loads `sentence-transformers/all-MiniLM-L6-v2`. First time this runs, it downloads ~90 MB of model weights from Hugging Face.
4. **§4 Stores** — opens the Chroma archive and either loads the cached FAISS index (`./faiss_pdf_index/`) or builds it from `Amber25.pdf`. First build takes a few minutes; subsequent runs load in under a second.
5. **§5 Merged retriever** — defines `hybrid_retrieve`. The smoke test at the bottom prints 5 hits for "What is Amber?" with at least `MIN_PDF=2` of them tagged `[pdf]`.
6. **§6 LLM + prompt** — initializes `ChatOllama` and the AmberRAG prompt template.
7. **§7 Answer chain** — defines `answer_chain = prompt | llm | parser`.
8. **§8 Query helper** — defines `query_rag`.
9. **§9 Evaluation suite** — runs all 8 test questions through the pipeline. Wipes `rag_results.json` at the start, then appends one record per question.

Expected runtime end-to-end: 3–10 minutes depending on hardware, dominated by Ollama generation.

After it finishes you should see a new file `rag_results.json` next to the notebook.

### 2. `Sauce_Amber_RAG_Combined_ChatGPT.ipynb` — ChatGPT + RAG

Identical retrieval pipeline, only the LLM differs (`gpt-4o-mini`). Run top to bottom. This one is much faster than the Ollama notebook because OpenAI's API is faster than a local 8B model on most laptops — expect roughly 1–2 minutes for all 8 questions.

If you get an error about `OPENAI_API_KEY`, you forgot to export it before launching Jupyter. Either restart Jupyter with the env var set, or set it in the notebook with `os.environ["OPENAI_API_KEY"] = "..."` (don't commit the notebook afterward).

### 3. `Sauce_Amber_RAG_Combined_NoRAG.ipynb` — both LLMs, no retrieval

This notebook strips out retrieval entirely. Each question goes through both `llama3.1:8b` and `gpt-4o-mini` directly, with a stripped-down prompt that allows each model to answer from training knowledge. Side-by-side answers print per question.

Use this as the "control" — what each model knows without your archive and PDF.

## Outputs

After running the primary notebook, you'll have:

- **`./faiss_pdf_index/`** — cached FAISS index built from `Amber25.pdf`. Delete this directory to force a rebuild (e.g., if you change `CHUNK_SIZE` or swap PDFs).
- **`rag_results.json`** — structured record of every question, generated answer, and the top sources used. Schema per record:

  ```json
  {
    "question": "What is Amber?",
    "answer": "...",
    "sources": [
      {
        "store": "pdf",
        "page": 5,
        "source": "Amber25.pdf",
        "score": 0.21,
        "snippet": "first 500 chars of the chunk"
      }
    ]
  }
  ```

  This file makes it easy to diff results across runs or against the ChatGPT notebook (which doesn't write a JSON file by default — see "Extending" below if you want it to).

## How to compare results

The fastest way to read the comparison:

1. Run the Ollama+RAG notebook. Skim each answer + sources.
2. Run the ChatGPT+RAG notebook. The questions are identical, so scroll cell-by-cell against the first notebook.
3. Run the no-RAG notebook last. For each question, ask: does the bare LLM already know this? If yes, your RAG isn't earning much on that query. If no, RAG is doing real work.

Things to look for:

- **Hallucinated specifics from the bare LLMs.** Watch for confident citation of made-up AMBER flag names, default values, or filenames in the no-RAG outputs.
- **Source quality differences.** In the RAG outputs, the `[pdf]` sources should be authoritative (cite manual pages) while `[archive]` sources are anecdotal. Better answers tend to lean on PDF sources for definitions and archive for edge cases.
- **Prompt adherence.** ChatGPT will follow the "do not mention your role" and "cite sources at the start" rules more strictly than llama3.1:8b.

## Troubleshooting

**`ConnectionRefusedError` against `localhost:11434`.** Ollama isn't running. Start it with `ollama serve` in another terminal.

**`OPENAI_API_KEY is not set`.** The notebook's setup cell deliberately raises this. Export the key in the shell you launched Jupyter from, then restart the kernel — env vars set in a notebook cell don't retroactively appear in `os.environ` for prior cells.

**`FileNotFoundError: Amber25.pdf`.** The file isn't where the notebook expects it. Drop the PDF next to the notebook, or edit `PDF_PATH` in the Configuration cell.

**`PermissionError` reading `/opt/chromadb/data/prompt_db`.** The Chroma directory isn't owned by your user. Either move it (`mv /opt/chromadb/data/prompt_db ~/chromadb/prompt_db` and update `ARCHIVE_DB_PATH`) or `sudo chown -R $USER /opt/chromadb`.

**Archive store shows `0 vectors`.** The Chroma database exists but the collection name is wrong, or it was built with a different embedding model. Confirm the collection is `amber_messages` and that it was embedded with `sentence-transformers/all-MiniLM-L6-v2` — using a different embedder breaks score comparability across the two stores.

**FAISS index keeps rebuilding every run.** The notebook writes the cache to `./faiss_pdf_index/`. If that directory keeps getting deleted (e.g., by a `.gitignore` cleanup or by running from `/tmp`), the rebuild path is taken every time. Either run from a persistent directory or change `FAISS_INDEX_DIR` to an absolute path.

**The PDF FAISS build is very slow.** Embedding ~3,800 chunks with MiniLM on CPU takes a few minutes; this is normal. It only happens once — subsequent runs load the cached index in under a second.

**`ImportError: langchain-openai`.** The package was installed but Jupyter is using a different Python interpreter than your shell. Inside the notebook, run `!which python` and `!pip list | grep langchain` to confirm. The fix is usually to install packages with `%pip install ...` inside the notebook itself.

## Extending

A few natural next steps if you keep iterating on this:

- **Save ChatGPT and no-RAG answers to JSON** the same way `query_rag` does. Then you can diff three JSON files against each other programmatically.
- **Add a reranker.** Cross-encoder rerankers like `BAAI/bge-reranker-base` over the top 20 merged hits typically beat raw vector similarity by a wide margin on quality.
- **Add BM25 alongside vector search.** AMBER-specific terms (`ntc=2`, `nastruct`, `fd_helix`) benefit from keyword sensitivity that dense embeddings can miss.
- **Track scores over time.** Once `rag_results.json` exists for multiple runs, you can build a small dashboard or just a Pandas comparison to see whether changes to chunking, `MIN_PDF`, or the prompt move the needle.
